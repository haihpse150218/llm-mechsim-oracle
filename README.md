# Executable oracles for LLM-generated mechanism simulators

Data, code and manuscript for the paper

> P. H. Hoang, *Where and What: Executable Oracles as Acceptance Gates and Repair Feedback for LLM-Generated Mechanism Simulators* (manuscript, 2026).

An LLM writes an interactive three.js simulator of a mechanism (four-bar, Geneva drive, planetary gear set, disk cam, Watt II six-bar, Jansen leg, Chebyshev lambda, Peaucellier–Lipkin) from a short prose description. The oracle loads the page in headless Chrome, samples its pure `window.SIM.render(t)`, and checks it in five families (META, PARAM, DESIGN, GT, PANEL) using the simulator's own declared parameters plus a small set of design rules per mechanism type. The study compares the oracle with a VLM reviewer, and uses it as the acceptance gate and feedback source of an iterative repair loop with feedback at different levels of specificity.

Models: `claude-sonnet-5-5` and `claude-haiku-5-5`, run as Claude Code sub-agents, 8–13 November 2026.

## Reproducing

Requirements: Node.js ≥ 20, Google Chrome (the oracle launches Playwright with `channel: 'chrome'`), Python 3 with matplotlib for Figure 3, and a LaTeX distribution for the manuscript.

```bash
cd pilot
npm install                      # Playwright 1.58.2
node oracle/run_oracle_lite.mjs reference_lite/*.html             # all references PASS
node oracle/run_oracle_lite.mjs gen_lite/*/*.html --out /tmp/g.jsonl   # verdicts of the generated simulators
node stats/stats.mjs             # statistics -> stats/STATS.md
cd ../paper/draft
node make_tables.mjs && node check_refs.mjs && node sync_overleaf.mjs
cd ../overleaf && pdflatex main && bibtex main && pdflatex main && pdflatex main
```

The generation, VLM review and repair steps were performed by LLM sub-agents; their inputs (task files, prompts, feedback) and outputs (HTML files, replies) are all stored, so every verdict and statistic can be recomputed without calling a model.
